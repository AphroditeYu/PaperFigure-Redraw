# Output modes and verification

- **Quantitative charts:** save PNG and vector PDF or SVG; provide a runnable Python script and CSV/TSV/XLSX source data. Prefer supplied underlying data, then author data, then measured estimates from the visible plot. Preserve uncertainty, scales and missing data; do not infer raw distributions from summary charts. For each digitized series, document calibration points, axis scale, units, resolution and approximate accuracy. Use matplotlib or another appropriate library; only use synthetic data if the user explicitly requests a clearly labeled illustrative example.
- **Flowcharts and diagrams:** create PPTX with editable native shapes, text, connectors and arrowheads, including grouping and layering. Provide a preview image and generation script where practicable. A bitmap inside a slide is not an editable recreation. For complex scientific schematics, identify components that can only be approximated.
- **Tables:** create XLSX with editable cells, sensible data types, merged headers, number formats, borders and widths. Transcribe values exactly where legible; mark uncertain cells explicitly and explain them in a separate notes sheet. Do not replace formulas with invented formulas. Export a preview and provide source/transcription if useful.
- **Photos, maps, complex illustrations and hybrid panels:** reconstruct data-driven elements where evidence supports it. Preserve source images as labeled reference crops when necessary, and explicitly identify raster components. Never imply that an AI-generated biological image is experimental evidence.

Verify numerical values, legends, labels and scale against the source. Render generated charts, slides and sheets when tooling allows and visually inspect at publication size. Reopen PPTX and XLSX, inspect native object/cell structure and test editing when possible. Record which checks were actually performed; note font substitutions and differences. Include dependencies and a command to regenerate each output. Avoid relying solely on pixel similarity when line weights, fonts or anti-aliasing differ.

## Digitization quality gates

For raster charts, explicitly calibrate axes from labeled ticks and record pixel coordinates and axis transform. Mask legends, labels, censor marks, gridlines, and other non-data marks before extracting curves. Color alone is insufficient: enforce appropriate continuity and, for survival curves, non-increasing behavior, but never silently interpolate across overlaps or occlusion. Mark missing segments and review against the original at full resolution. Keep measured pixel coordinates and digitized values, and distinguish approximate plotted points from individual-level observations. For complex composite biomedical figures, make a panel-by-panel inventory: reconstruct quantitative plots and editable text while preserving source image crops for blots and microscopy; do not generate substitute experimental images. A partial or missing panel remains partial even if the overall layout looks similar.

### Repeatable extraction and author-data reconciliation

When an image filename, caption, DOI or article is identifiable, look for the paper’s figure-specific source data and code before digitizing, when access is available and permitted. Record the exact source link and match panels, species, labels and units. Compare source values and visual plot and report discrepancies, including replicate counts and definitions; do not silently assume every column is an independent replicate. Preserve the original source workbook as provenance and deliver derived editable data with documented formulas. If network lookup fails, proceed with visual estimates and explain the limitation.

For simple vertical filled bars on a linear zero-baseline chart, `scripts/extract_bars.py IMAGE CONFIG.json --out OUTPUT` offers a reproducible starting point. It needs Pillow, NumPy, openpyxl and matplotlib. The agent must visually specify each panel’s `name`, `y0` zero-baseline pixel, `y1` pixel for value 1, `centers` (x pixels), and corresponding `labels`, in a JSON object with a `panels` array. It scans only gray or green bars connected to baseline; it does not handle stacked, negative, floating, non-linear, other-colored, or occluded bars. It may reject valid charts or measure a wrong connected mark; check each value and rendered output. It cannot extract error bars. Values are estimates, not original observations. If conditions do not match, choose another method; never use it blindly.
